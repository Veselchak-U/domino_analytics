# Инструменты

AST Index 3.55.0 установлен локально в tools/ast-index, версия и зависимости
закреплены package-lock.json из рабочего соседнего проекта. На Windows используй
только .\ast-index.cmd: кеш остаётся в .analysis/ast-index-cache. На других ОС
задавай AST_INDEX_CACHE_DIR явно либо используй node tools/ast-refresh.js.

Для структуры кода используй explore, symbol, refs, outline и imports. Перед
следующим структурным запросом после группы правок выполни npm run index (rebuild);
после изменения корней также rebuild. В JSON проверяй pagination.truncated и сужай запрос при обрезке.
Индекс не доказывает отсутствие динамических вызовов. Для известного участка читай
файл напрямую; для строк, Markdown и JSON используй rg. При отказе индекса — rg
как запасной путь с указанием ограничения. Не запускай бесконечные rebuild или watch.

Хуки npm: postinstall устанавливает локальный инструмент и строит индекс;
pretest/precheck обновляют его; npm start и корневые скрипты запуска не обновляют
индекс и не требуют установленного AST Index при готовых зависимостях приложения.
Проектный .codex/hooks.json обновляет индекс на SessionStart (startup/resume/clear),
без повторного запуска после compact. Хук ищет корень вверх от cwd, поэтому
работает и из подкаталогов. Новый хук нужно доверить в интерфейсе хуков Codex;
автоматическое срабатывание проверяется на следующей сессии. Обновление перед структурным
поиском в процессе разработки остаётся обязательным. В текущем каталоге без Git
у версии 3.55.0 update захватывает node_modules вопреки фильтрам. Поэтому здесь
после группы правок используй rebuild (или npm run index), хуки также выполняют
rebuild. После изменения версии проверь оба режима, прежде чем вернуть update.
Глобальные настройки Codex,
Claude и Git не изменяются. Соседние проекты не включаются в индекс.

Читай только относящиеся к задаче правила и зависимости.
Дочитывай обрезанный вывод. Не перечитывай неизменившиеся файлы без причины.
PowerShell-команды должны сохранять Unicode; не смешивай оболочки при операциях
с файлами. Bash-скрипты запускай через Git Bash. Не удаляй чужие изменения.
Команды запускай из корня проекта. Не ставь инструменты повторно без необходимости.
