# service-boundaries Specification

## Purpose
Разделить интерфейс и вычислительный бэкенд на независимо запускаемые приложения с REST-обменом и удобным локальным управлением в Docker Desktop.

## Requirements

### Requirement: Два сервиса и REST
Frontend и backend SHALL иметь отдельные команды запуска и контейнерные образы. Backend MUST NOT раздавать интерфейс, frontend MUST NOT владеть БД или исполнять полный перебор. URL API SHALL настраиваться без изменения frontend-исходников. В Docker Desktop только frontend SHALL публиковаться на loopback:3210.

#### Scenario: Разделённый запуск
- **WHEN** запущены два сервиса Docker Compose
- **THEN** интерфейс и REST доступны через frontend, backend не публикует порт, прямой запрос статики к backend даёт 404

#### Scenario: Ошибка backend и безопасность
- **WHEN** backend недоступен либо frontend получает чужой Host/Origin
- **THEN** интерфейс не падает, API-запрос получает 503 в первом случае, небезопасный запрос отклонён в остальных

### Requirement: Локальные команды и данные
Корневые бат-файлы SHALL запускать, останавливать, обновлять и перезапускать оба сервиса, показывать состояние/логи и создавать резервную копию БД. Обычные команды MUST NOT удалять постоянный том. Ошибка Docker SHALL быть понятной по-русски.

#### Scenario: Обновление и резервная копия
- **WHEN** выполнены обновление, остановка и последующий запуск либо команда backup
- **THEN** игры и готовый анализ сохранены, backup создаёт согласованную копию, которую можно открыть отдельно
