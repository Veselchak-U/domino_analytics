## MODIFIED Requirements

### Requirement: Два сервиса и REST
Frontend и backend SHALL иметь отдельные команды запуска и контейнерные образы. Backend MUST NOT раздавать интерфейс, исполнять полный перебор или игровые переходы; frontend-сервер MUST NOT владеть БД или выполнять вычисления вместо браузера. Браузер SHALL выполнять вычисления на клиентском компьютере и обмениваться с backend исходниками и готовыми данными через REST v1. URL API SHALL настраиваться без изменения frontend-исходников. В Docker Desktop только frontend SHALL публиковаться на loopback:3210. Browser-safe вычислительные модули и worker SHALL раздаваться frontend по явному списку без доступа к произвольным серверным файлам. Несколько доверенных клиентов SHALL независимо считать и пользоваться общей библиотекой; глобальная вычислительная очередь отсутствует.

#### Scenario: Разделённый запуск
- **WHEN** запущены два сервиса Docker Compose
- **THEN** интерфейс, worker и REST v1 доступны через frontend, backend не публикует порт, прямой запрос статики к backend даёт 404, вычисления выполняются в браузере

#### Scenario: Ошибка backend и безопасность
- **WHEN** backend недоступен либо frontend получает чужой Host/Origin
- **THEN** интерфейс не падает, API-запрос получает 503 в первом случае, уже начатый локальный расчёт продолжается, небезопасный запрос отклонён в остальных

#### Scenario: Независимые клиенты
- **WHEN** два браузера считают разные раунды, третий читает библиотеку
- **THEN** все клиенты обслуживаются без вычислительного 409 и серверного solver; отмена первого расчёта не меняет второй

#### Scenario: Границы статических ресурсов
- **WHEN** запрошен разрешённый worker либо произвольный файл src, node_modules или БД
- **THEN** worker загружается с действующей CSP, произвольный серверный файл не выдаётся


### Requirement: Локальные команды и данные
Корневые бат-файлы SHALL запускать, останавливать, обновлять и перезапускать оба сервиса, показывать состояние/логи и создавать резервную копию БД. Обычные команды MUST NOT удалять постоянный том. Ошибка Docker SHALL быть понятной по-русски.

#### Scenario: Обновление и резервная копия
- **WHEN** выполнены обновление, остановка и последующий запуск либо команда backup
- **THEN** игры и готовый анализ актуальной схемы сохранены; при первом переходе со старой схемы БД заменяется пустой по analysis-service, backup создаёт согласованную копию, которую можно открыть отдельно
