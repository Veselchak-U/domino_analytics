## Why

Текущий backend проверяет игровые переходы и выполняет полный перебор в единственном worker. Длительный расчёт занимает ресурсы сервера и мешает другим клиентам начать собственный анализ. Нужен сервер с минимальными ресурсами, обслуживающий общую библиотеку исходных журналов и готовых результатов, при независимых вычислениях на компьютерах клиентов.

## What Changes

- Перенести полную проверку журнала, игровые правила, точный solver, анализ истории, ветвей и учебных упражнений в браузерный модульный Web Worker. Сохранить W/N, BigInt, дедупликацию, кратность путей и ограниченный кеш поддеревьев.
- Оставить backend хранение, выдачу, версионирование и минимальную структурную проверку загружаемых журналов и результатов. Сервер не воспроизводит партию и не пересчитывает анализ.
- Сверить контракт с [источником спецификации игры](../../../../docs/game-spec-source.md): обязательное playedAt и идентичность партии по моменту её начала и составу игроков. Форматирование файла не создаёт новую партию; изменение игрового содержания при той же идентичности даёт конфликт без перезаписи.
- Переработать существующий API v1 для получения и идемпотентной загрузки завершённых результатов, сохранив префикс /api/v1 и алиас /api. Разделить локальную готовность расчёта и подтверждённое сохранение на сервере.
- Обеспечить независимость клиентов и атомарное разрешение одновременных публикаций одного результата без серверной блокировки на время расчёта.
- **BREAKING в API v1**: убрать серверные вычислительные POST /analyze, /branch, /lesson и API jobs; заменить контракт проверенного сервером импорта структурно проверенным импортом и полным клиентским воспроизведением, а выдачу всех анализов — постраничным manifest и отдельным чтением результата. Frontend и backend обновляются совместно; параллельная версия API не вводится.
- Сохранить интерфейс, обучение, локальную поставку, SQLite и резервные копии актуальной БД. Старую БД заменить новой схемой без переноса прежних записей, по прямому указанию пользователя.
- Обязательный вычислитель — CPU клиента через Web Worker; GPU/WebGPU, WASM и распределение одного дерева между устройствами не входят в эту реализацию. Они не являются условием работы или основанием обещать ускорение.

## Capabilities

### New Capabilities
- `browser-computation`: полная клиентская проверка и расчёт, локальный жизненный цикл, точность, доступность интерфейса и восстановление после ошибок.

### Modified Capabilities
- `service-boundaries`: вычисления в браузере, серверы интерфейса и хранения без solver, независимые клиенты.
- `analysis-service`: загрузка и получение готовых результатов вместо серверных заданий, версии, минимальная проверка и конкурентная публикация.
- `game-library`: структурный импорт на сервере и полная проверка в браузере, сохранение источников и старой библиотеки.
- `round-analytics`: клиентское происхождение аналитики и прогресса, хранение на выбранном сервере.
- `alternative-branches`: восстановление и анализ ветки на клиенте.
- `team-tactics-training`: локальная проверка и расчёт встроенных упражнений.
- `local-vm-deployment`: поставка серверов без вычислительной роли и сохранение библиотеки при обновлении.

## Impact

Затрагиваются src/server.js, src/storage.js, src/input.js, src/game.js, src/solver.js, src/analysis.js, src/worker.js, src/lessons.js, public/app.js, src/frontend.js, shared/, контракты API, тесты и контейнерная поставка. Конкретное размещение переносимых модулей описано в design.md. CLI остаётся отдельным локальным способом проверки и анализа на общем игровом ядре.

Сервер хранит клиентские результаты без математического подтверждения их правильности; структурная целостность не доказывает полный перебор. Принята общая библиотека доверенных клиентов в существующей закрытой модели доступа. Публичный многопользовательский сервис с учётными записями и разграничением данных — отдельное изменение.
