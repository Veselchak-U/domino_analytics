## Context

Сервер слушает 127.0.0.1, использует проверки Host/Origin и хранит игры/задания/результаты в памяти. Docker на машине разработки отсутствует; реальное контейнерное испытание возможно на целевой VM. Более широкое проектирование split-backend-frontend отложено владельцем.

## Goals / Non-Goals

**Goals:** переносимый образ linux/amd64, Compose, архив релиза без registry, одна команда установки/обновления, healthcheck и откат.

**Non-Goals:** постоянная БД, два сервиса, публичные домены, облака, провижининг гипервизора. Поставляется инструкция создания Ubuntu VM, а не импортируемый образ диска гипервизора.

## Decisions

- Один контейнер текущего приложения. Docker Engine и Compose plugin на Ubuntu 24.04; Node 22 внутри образа. Такой формат затем переносится на российский VPS.
- HOST допускает только 127.0.0.1 или 0.0.0.0; по умолчанию 127.0.0.1. Проверки Host/Origin остаются прежними. Compose публикует 127.0.0.1:3210 и не даёт прямого доступа из LAN. Туннель сохраняет тот же локальный порт; это не публичная сетевая конфигурация.
- Сборка вне рабочей VM: Dockerfile устанавливает production-зависимости без lifecycle hooks, копирует только src, public и contracts. Установка npm не включает AST Index. Корневая .dockerignore работает как разрешительный список.
- Архив: image.tar, compose.yaml, image.env, dominoctl.sh и SHA256SUMS. Без обязательного внешнего registry. Контрольная сумма обнаруживает повреждение, не заменяет доверие источнику; доставлять по SSH.
- Управление bash-скриптом: проверка релиза, flock на каталог установки, docker load, Compose up --wait. Все служебные файлы версии копируются в отдельный releases/<version>; current/previous — текстовые указатели с номером версии, заменяемые через rename. При ошибке новой версии запускается старая, проверяется код здоровья. Данные отдельно от релиза; rollback не удаляет каталоги и образы.
- data/examples монтируется только для чтения. Доступные примеры задаются этим каталогом вместо соседнего проекта. Резервная копия каталога до обновления сохраняет примеры, но не восстанавливает Map сервера. БД и миграций на данном этапе нет.
- Исходный бюджет 2 vCPU / 4 ГБ VM, контейнер до 3 ГБ. Нельзя обещать достаточность для каждого полного перебора; приложение не переходит на выборку при нехватке памяти.

## Risks / Trade-offs

- Перезапуск теряет игры/расчёты памяти → завершать нужные действия до обновления, повторно импортировать исходный файл; постоянное хранение отдельным изменением.
- Недоступен Docker в текущей среде → shell-синтаксис, сетевые регрессии и сценарии управления с подменой Docker проверяются здесь; сквозной smoke-скрипт предоставляется для целевой VM, факт отсутствия реальной проверки явно записывается.
- Нет публичной авторизации → исключительно loopback/SSH, смена на 0.0.0.0 порта хоста не предлагается.

## Migration Plan

На Linux машине сборки создать релиз; перенести каталог на VM по SCP и выполнить install. Следующий релиз установить через update; для возврата использовать rollback. Прежние Windows-команды запуска сохраняются. Облачные ресурсы не создаются.
