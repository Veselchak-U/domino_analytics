## Why

Для анализа партии сейчас нужен готовый JSON. Нужна форма хронологической записи раундов по наблюдаемым ходам и остаткам, без предварительного ввода четырёх рук, с проверками и экспортом в актуальный формат domino_spec.

## What Changes

- Добавить кнопку «Записать партию» рядом с загрузкой JSON и отдельный экран редактора с постоянным заголовком даты, участников и правил.
- Записывать ходы с выбором участника, подсказками камней/краёв, проверкой очереди, стыковки, повторов и противоречий пасов; показывать цепочку после каждого действия.
- Определять выход или рыбу по полной колоде и числу сыгранных камней. В конце предложить распределить остатки, восстановить начальные руки и полностью проверить раунд общим игровым ядром.
- Показывать исход раунда, записанный счёт, забор и яйца; завершать партию по её лимиту и правилам.
- Синхронизировать JSON Schema с источником: status complete/incomplete, отсутствие статуса означает complete. Незавершённая партия содержит минимум один полностью завершённый раунд и не имеет корневого result; частичные раунды не экспортируются.
- Позволить скачать JSON, загрузить incomplete JSON для продолжения либо скачать завершённую партию и передать её в существующий клиентский расчёт/сохранение. Сервер явно отклоняет incomplete без вычислений.

## Capabilities

### New Capabilities
- `game-entry`: форма записи, последовательные ходы, остатки, восстановление раздачи, счёт и экспорт/продолжение.

### Modified Capabilities
- `round-analytics`: обновлённое право захода без яиц со второго раунда даже при нулевой записи.
- `game-library`: распознавание status и явный отказ серверного импорта незавершённой партии.

## Impact

Затрагиваются public/index.html, app.js, style.css, новые модули редактора, общий разбор входа и generated Schema, tests и документация. HTTP API v1, формат kozel-game-v1, движок полного перебора и схема SQLite сохраняются. Исходные пользовательские JSON не переписываются; новый status complete семантически равен его отсутствию при дедупликации.
