## Context

Мотивация — proposal.md. Источник domino_spec проверен на commit fef6b1bb864ada44727ea7f3b3fd273418dc4180: корневой status complete/incomplete, отсутствие равно complete, при incomplete корневой result запрещён, каждый раунд остаётся полным. Пользователь выбрал ввод ходов без предварительных рук, затем остатков; частичные раунды не сохраняются в JSON.

## Goals / Non-Goals

Goals: удобная последовательная запись с проверками, восстановление точной раздачи, экспорт/продолжение по источнику и передача готовой партии существующему клиентскому анализу. Non-Goals: частичные раунды в файле, серверное хранение черновиков, новый API, изменение начислений или W/N, автоматическое сохранение формы между сессиями.

## Decisions

### Компоненты и владельцы

| Компонент | Состояние и обязанности |
|---|---|
| shared/game-entry.js | Чистые переходы записи: неизменяемый общий заголовок, завершённые раунды и временный активный раунд; проверки, подсказки, остатки, экспорт |
| shared/input.js | Полное воспроизведение готового документа, опциональный приём incomplete только для формы; существующий parseGame по умолчанию принимает complete |
| public/game-entry.js | Один экземпляр редактора в памяти вкладки, события формы, выбор камней, цепочка, счёт, скачивание и загрузка |
| public/app.js | Открытие редактора и передача завершённого JSON в существующий importSource/AnalysisClient |
| Backend | Только прежняя структурная проверка и явный отказ INCOMPLETE_GAME; ни редактор, ни игровой движок сюда не импортируются |

Первый экран задаёт playedAt с явным часовым поясом, четыре уникальных имени по seat, имена двух команд с партнёрами 1/3 и 2/4, вариант рыбы и лимит. После начала заголовок фиксируется; при возврате из других экранов форма сохраняется в памяти. Кнопка новой партии требует явного действия и не сбрасывает ввод при обычном закрытии редактора.

### Что известно до остатков

Начальная колода — все 28 камней, по 7 у игрока. Временная запись хранит действия, сыгранные камни каждого игрока, глобальную маску сыгранного, открытые концы, очередь и последнего недубля. В первом раунде, а также в withEggs при нулевой записи, первый актор выбирается пользователем, но только с 1–1. В withoutEggs со второго раунда независимо от счёта, а в withEggs после открытия записи стартует finished_player предыдущего раунда любым камнем. Новое правило меняет version.rules на 2 без изменения схемы БД; старый кеш не выдаётся как актуальный.

Каждый ход проверяет очередь, действие/ориентацию, уникальность камня, вместимость руки и известные противоречия пересдачи. Пас добавляет запрет владеть ещё не сыгранными камнями, совместимыми с концами в тот момент. Позднейший ход запрещённым камнем отвергается. Для неизвестных оставшихся владельцев проверяется существование распределения по ёмкостям оставшихся рук с этими запретами: для всех 15 подмножеств четырёх игроков число камней, чьи возможные владельцы лежат только в подмножестве, не превышает его ёмкость (условие Холла с ёмкостями). Это точная проверка совместимости записи с ограничениями пасов, не оценка побед и не выборка.

Без начальных рук невозможно утверждать, что наблюдаемый пас был допустим именно в реальной раздаче. UI прямо поясняет: подсказки совместимы с известной записью; полная проверка рук, условий пересдачи и пасов выполняется после ввода остатков. Численные тактические рекомендации и solver для формы не запускаются.

Выход определяется после седьмой выкладки игрока. Рыба — когда ни один ещё не сыгранный камень полной колоды не подходит ни к одному открытому концу. Пропуски не расходуют камни; допустимый оставшийся дубль предотвращает рыбу, дубль не меняет рыбака. При выходе победитель раунда известен сразу. При рыбе с яйцами сравнение остатков и итог партии до их ввода не выдумываются; UI сообщает, что итог будет рассчитан после остатков.

### Остатки и завершение раунда

После терминального хода форма предлагает визуально распределить все оставшиеся камни по игрокам с указанием требуемого количества 7 минус число их выкладок. Указанный владелец не должен противоречить пасам и ёмкости руки. Пустая рука выходящего отображается автоматически. Из сыгранных камней плюс остатков каждого игрока восстанавливается полный deal. После проверки 28 уникальных камней, рук по семь и пересдачи раунд полностью воспроизводится общими applyMove/settle. Результат формируется общей recordedResult; контекст счёта, забор и яйца переносятся на следующий раунд без отдельной формулы в UI.

До подтверждения результат не попадает в список завершённых раундов. Можно отменить последний ход и исправить запись, не теряя завершённые предыдущие раунды. После подтверждения раунда UI показывает начисления/накопления, позволяет просматривать закрытые раунды и начать следующий; после завершения партии новый раунд недоступен.

### Экспорт и восстановление

Единственный сохраняемый формат — актуальный kozel-game-v1. В нём минимум один полностью завершённый раунд. Пока активный раунд содержит неподтверждённые ходы, обе кнопки выгрузки отключены с объяснением; не экспортируется молча только старый префикс и не создаётся частичный раунд. Пустой ещё не начатый следующий раунд не препятствует выгрузке предыдущих завершённых.

Незавершённая партия получает status incomplete, не имеет корневого result, имя заканчивается _incomplete.json. Загрузка этой кнопкой требует именно incomplete и полное воспроизведение всех его раундов, включая отсутствие окончательного исхода партии; общие данные и предыдущие раунды неизменны, следующий раунд начинается без счёта по умолчанию. Полностью завершённая партия получает status complete и result; она скачивается отдельно либо скачивается и передаётся прежнему клиентскому анализу и сохранению. Никакого прямого запроса /analyze к серверу.

Схема источника обновляется без смены format/API/БД. validateSource по умолчанию отказывает incomplete после схемы; форма явно запрашивает разрешение incomplete. Канонизация содержимого удаляет только status complete, чтобы старый файл без поля и новый с complete не конфликтовали в уже существующей библиотеке. Идентичность playedAt + игроки не меняется. При ошибке загрузки формы прежнее состояние не заменяется.

### Матрица проверки

| Состояние | Экран и разрешённое действие |
|---|---|
| Только заголовок / нет закрытых раундов | Ввод первого раунда, экспорт недоступен |
| Ввод ходов | Цепочка, проверяемые подсказки, отмена; экспорт недоступен |
| Выход/рыба, остатки не заполнены | Назначение всех оставшихся камней, подтверждение после полного распределения |
| Подтверждён раунд, партия продолжается | Счёт, экспорт incomplete или следующий раунд |
| Партия завершена | Итог, экспорт complete или экспорт + расчёт/сохранение; следующего раунда нет |
| Загружен incomplete | Полное воспроизведение, прежний заголовок/счёт и следующий раунд |
| Ошибочный файл/ход | Контекстная ошибка, состояние и цепочка не меняются |

## Risks / Trade-offs

- Неизвестные руки не позволяют проверить фактический пас до остатков → прозрачная промежуточная проверка и обязательное полное воспроизведение до закрытия раунда.
- Полный JSON не может сохранить половину раунда → отключённый экспорт и объяснение; при выходе со страницы с вводом используется штатное предупреждение браузера.
- Восстановленный deal может требовать пересдачи → ошибка подтверждения с сохранением ходов/остатков для исправления, без неверного результата.
- Импорт больших журналов → прежние лимиты 5 МиБ, 1024 раунда, 128 действий и строгий JSON; solver в редакторе не используется.

## Validation

1 ноября 2026 года: npm test — 137 успешных тестов; npm run check — схема, generated-файлы, синтаксис и ссылки правил без ошибок. Новые проверки покрывают восстановление всех трёх раундов примера, точное совпадение deal/moves/result, запрет экспорта активного раунда, статусы и отказ API без записи, совместимость digest и повторного импорта complete, очередь/края/повторы/пасы, остатки, пересдачу, оставшийся дубль и заход при нулевой записи обоих вариантов.

В браузере на изолированном сервере с БД в памяти: введены все три раунда через UI, показан итог 163:0 и победитель Юг, скачаны incomplete/complete, incomplete загружен для продолжения, ошибочный остаток отклонён без потери ввода, выполнены клиентский точный расчёт и сохранение всех трёх раундов («готово 3 из 3»). Проверены возврат в редактор, отмена хода, отмена/подтверждение замены данных внутри страницы и переход к тактике. На ширине 390 px общая форма и подсказки не создают горизонтального переполнения. Ошибок консоли в проверке формы и расчёта нет. Снимки сохранены локально в .analysis/game-entry-desktop.jpg и .analysis/game-entry-narrow.jpg; рабочая БД и исходные игровые JSON не затрагивались.
