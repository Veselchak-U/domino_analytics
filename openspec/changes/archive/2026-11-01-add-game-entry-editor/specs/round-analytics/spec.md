## MODIFIED Requirements

### Requirement: Проверка и воспроизведение журнала
Клиентский вычислитель браузера SHALL принимать kozel-game-v1 по contracts/kozel-game.schema.json,
отклонять повторные ключи JSON и проверять игровые правила полным воспроизведением.
Исходные файлы MUST сохраняться. Backend SHALL выполнять только структурную проверку импорта по game-library, без игрового воспроизведения. Очередь задаётся seat, партнёры сидят напротив.
Первый заход обязателен с 1-1. В withEggs заход при счёте 0:0 также обязателен с 1-1, после открытия записи заходит finished_player предыдущего раунда любым камнем. В withoutEggs со второго раунда заходит finished_player предыдущего раунда любым камнем независимо от записанного счёта. Ориентация хода обязательна.
Клиентский вычислитель SHALL сверять исходы, начисления, переносы и завершение партии с журналом.

#### Scenario: Реальный журнал
- **WHEN** загружен корректный завершённый журнал
- **THEN** восстановлены руки и цепочка каждого шага всех раундов, итоги совпадают

#### Scenario: Ошибочный журнал
- **WHEN** повторён ключ, камень, место, нарушены очередь, ориентация, пас, условия раздачи или итог
- **THEN** возвращена понятная ошибка с местом, файл не изменён

#### Scenario: Заход без яиц при нулевой записи
- **WHEN** первый раунд withoutEggs завершён и обе записи остались нулевыми
- **THEN** второй раунд начинает finished_player любым камнем; в withEggs при тех же записях остаётся обязательным заход владельца 1–1
