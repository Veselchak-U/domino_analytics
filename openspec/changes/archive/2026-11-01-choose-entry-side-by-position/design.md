## Context

GameEntry уже владеет состоянием переноса и использует проверяемые переходы shared/game-entry.js. Изменяется только определение цели хода; мотивация — в proposal.md.

## Goals / Non-Goals

Цель — единое поле приёма с выбором стороны по горизонтальной координате. Распределение остатков и игровые правила сохраняются.

## Decisions

- Единственная цель board на контейнере поля. Вложенные камни попадают в неё через closest; отдельных зон краёв нет.
- clientX сравнивается с серединой свежего getBoundingClientRect поля при dragover и повторно при drop. Это учитывает прокрутку, масштаб и изменение ширины без кеширования геометрии. Ровно посередине выбирается right.
- Пустая цепочка всегда задаёт start. Для непустой используется выбранная по координате сторона, без попытки подменить её более подходящей.
- Выбранная сторона отображается фоном и подписью, допустимость — существующей подсветкой. dragleave очищает предпросмотр только при выходе за всё поле, а не при переходе между вложенными камнями.
- Владельцем состояния остаётся GameEntry; preview — только DOM-представление, ход возникает исключительно при drop.

## Risks / Trade-offs

- Точка захвата камня может отличаться от его центра → выбор привязан к позиции указателя при отпускании, как обычный перенос мышью; подсказка заранее показывает сторону.
- Нативный перенос ограничен на сенсорных устройствах → кнопочное управление сохранено.

Матрица: пустой активный раунд — заход в любой точке; непустой активный — выбор края по координате; завершённый неподтверждённый — только перенос остатков; подтверждённый просмотр — без переноса.
