## Context

Solver владеет двумя поколениями Map и общей таблицей терминальных результатов.
UI владеет roundAnalyses, выбранным analysis/stepIndex и фоновой очередью партии.

## Goals / Non-Goals

Goals: постоянная стоимость обновления оценки и выбор готовых раундов без
повторного анализа. Non-Goals: точное измерение heap, snapshot, новая политика
вытеснения, остановка фонового расчёта при просмотре готового раунда.

## Decisions

- Суммировать оценку байтов отдельно для recent, previous и общих терминалов.
  При ротации счётчики меняются вместе с Map. Общий терминальный результат
  учитывается один раз в terminals; записи поколений содержат только ключ и ссылку.
- Модель: числовой ключ позиции — 16 байт; строковый ключ терминала —
  24 байта заголовка + UTF-16 с выравниванием 8; Map-запись — 48,
  результат — 80, массив wins — 48, шесть BigInt — 16 байт заголовка и выделение
  по 8-байтовым словам. Разрядность leaves даёт верхнюю оценку каждого счётчика.
  Это приблизительная модель, не точный расход V8; GC, ёмкость heap и временные
  объекты не включаются. Измерение heap смешало бы кеш и остальную память.
- Обновление только при вставке, одно преобразование leaves в hex на результат;
  stats читает три числа. Дополнительной Map для учёта памяти нет.
- Чистый модуль public/format.js форматирует размер, HTTP публикует его как asset.
- Заголовок и ячейки раундов — обычные кнопки с data-round/aria-pressed.
  Единственный selectRound использует roundAnalyses и общий renderAnalysis;
  шаг сбрасывается в 0. Отдельного состояния выбранного раунда у таблицы нет.
- Флаг фонового расчёта отличает очередь от загрузки/основного анализа. Во время
  очереди готовыe колонки доступны, неготовые отключены. При свободном сервере
  неготовая колонка использует существующий startAnalysis.

## Risks / Trade-offs

Оценка зависит от устройства V8 → знак ≈ и описание модели в README.
Переключение во время очереди → фоновая задача сохраняет владение activeJob,
а выбранный analysis меняется только для отображения.
