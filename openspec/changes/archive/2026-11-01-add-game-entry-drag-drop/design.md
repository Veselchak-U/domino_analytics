## Context

GameEntry владеет состоянием формы; shared/game-entry.js выполняет неизменяемые проверяемые переходы. Сейчас UI строит отдельную кнопку для каждого сочетания камня и края. См. proposal.md для мотивации.

## Goals / Non-Goals

Цель — новый способ тех же переходов состояния. Игровые правила, контракт JSON, вычисления и хранение не меняются.

## Decisions

- Нативные dragstart/dragover/drop/dragend делегируются корню формы. Временное состояние переноса хранит только камень и ссылку на исходное entry. Оно не сериализуется; перерисовка отменяет перенос. Это не создаёт второго владельца игровых данных.
- Данные внешнего DataTransfer не принимаются: drop использует только внутренний перенос этой формы. Для края выбирается соответствующая запись moveSuggestions по stoneId. Отдельный алгоритм ориентации не нужен.
- Остатки передаются в setRemainders после удаления камня из всех прежних рук. Ошибка не меняет entry. Полная проверка остаётся в confirmEntryRound.
- Набор отображает все невыставленные камни, в остатках — только неназначенные. Назначенные камни находятся в карточках с доступной кнопкой возврата. Прежние кнопки ходов остаются дополнительным способом ввода.
- Нативное перетаскивание вместо Pointer Events достаточно для заказанной мыши, сохраняет обычный скролл и не требует глобального захвата указателя.

Матрица: активный незавершённый раунд принимает перенос только на заход/края; завершённый неподтверждённый — только в руки/набор; подтверждённый просмотр — без переноса. Отмена drag не меняет данные во всех режимах.

## Risks / Trade-offs

- Нативное перетаскивание ограничено на сенсорных устройствах → сохранён ввод кнопками с клавиатуры и касанием.
- DOM перестраивается после перехода → перенос очищается перед отображением, устаревшая ссылка не принимается.
- Без полного браузерного тестового фреймворка → node:test проверяет обработчики формы через минимальный DOM, дополнительно проверяется реальный браузер.
