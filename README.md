# Домино · Аналитика

Локальное веб-приложение для точного анализа командного «Козла». Загружает
завершённую партию `kozel-game-v1`, проверяет её воспроизведением и рассчитывает
все допустимые продолжения выбранного раунда с учётом права захода.

## Запуск

На Windows можно дважды щёлкнуть файл в корне проекта:

- `start.cmd` — запустить сервер;
- `start-browser.cmd` — запустить сервер и открыть браузер после его готовности.

Скрипты работают из любого текущего каталога. Если зависимости ещё не установлены,
они устанавливаются автоматически. Node.js 22+ должен быть установлен заранее.
Из PowerShell также можно выполнить `./start.ps1` или `./start.ps1 -OpenBrowser`.
Параметры `PORT` и `DOMINO_EXAMPLES_DIR` наследуются из окружения.

Нужен Node.js 22 или новее. Из каталога проекта в PowerShell:

```powershell
npm.cmd ci --cache .analysis/npm-cache
npm.cmd start
```

Откройте [локальное приложение](http://127.0.0.1:3210).
Загрузите JSON или выберите готовый файл из `C:\Projects\Home\domino_video_parser\out`.
Файлы с `needs-review` не предлагаются. Есть учебный пример с тремя раундами.
Можно выбрать раунд, двигаться кнопками, ползунком, нажатием на график или строку
истории. Стрелки клавиатуры также переключают шаги, когда фокус вне элементов ввода.
«В игре» у альтернативы отмечает реальный выбор, включая эквивалентную зеркальную выкладку.

Изменение порта и каталога примеров:

```powershell
$env:PORT = '3211'
$env:DOMINO_EXAMPLES_DIR = 'C:\MyGames'
npm.cmd start
```

Сервер слушает только `127.0.0.1`. Игровые данные остаются на компьютере.
Остановка — Ctrl+C. Файлы не изменяются; кеши анализа находятся только в памяти.
Кеш AST Index — отдельный служебный индекс исходников в `.analysis/ast-index-cache`.

## Модель расчёта

**Вероятность победы = число конечных ветвей с победой команды / число всех конечных ветвей.**
Это равномерное распределение по листьям, а не случайный выбор на каждой развилке
и не прогноз оптимальной игры. Все четыре руки известны из раздачи.

- Исходы — листья развёрнутого дерева. Повторяющие друг друга продолжения одного
  узла объединяются. Позиция определяется руками, открытыми концами, очередью и
  последним выложившим недубль; зеркальные цепочки эквивалентны.
- Если разные последовательности позже приходят к одной позиции, её поддерево
  вычисляется один раз, но листья учитываются для каждой последовательности.
- Карточка количества ходов показывает минимум и максимум действий до окончания
  раунда из начальной раздачи. Минимум передаётся как `minDepth`, максимум — `depth`.
  Заход и обязательные
  пропуски считаются. Полная блокировка завершает раунд немедленно, без четырёх
  дополнительных пропусков. У терминального узла один лист и глубина ноль.
- Перед первым ходом показана база: все допустимые заходы назначенного игрока.
  После каждого записанного действия шансы рассчитаны для оставшегося поддерева.
  Изменение показано как разность вероятностей со знаком % относительно предыдущего шага.
- Выборки, эвристического отсечения и ограничения глубины нет. Количества листьев
  и побед считаются `BigInt`, в API и CLI передаются десятичными строками. В веб-интерфейсе
  все проценты округляются до двух знаков. Точные числители и знаменатель видны рядом с ними.

Кроме вероятностей интерфейс показывает три характеристики: изменение шансов,
количество допустимых действий и вероятность рыбы (включая долю рыбы с яйцами).
Технической карточки начального счёта с числом обработанных позиций и временем нет.
Число листьев и границы количества ходов всего раунда
показаны отдельно и не меняются при перемещении по истории.

В блоке вероятностей добавлен график «Влияние хода» с общей шкалой ходов. P1–P4 — места
игроков, полные имена показаны в легенде. Столбец выше нуля означает рост шанса
команды автора, ниже — снижение; нажатие выбирает тот же шаг на обоих графиках.
На узком экране графики прокручиваются вместе по горизонтали.

Вариант из журнала показан слева и в шапке: «Козёл, 2x2, до 50, без яиц»
(лимит и яйца соответствуют загруженной партии). Управление шагами доступно
после графиков и перед «Историей раунда»; обе панели синхронизированы.
Пояснения графиков и правил расчёта собраны в нижнем FAQ с раскрывающимися вопросами.
Столбцы одного хода
соприкасаются, промежутки сохраняются между группами ходов.
Таблица вклада игроков — первый блок дашборда, перед карточками исходов и количества ходов.
Нажатие на заголовок или значение колонки «Раунд N» выбирает этот раунд,
выделяет колонку и переключает все подробности на шаг 0. Готовые раунды доступны
во время фонового расчёта остальных. Неготовые колонки в это время отключены;
после остановки расчёта их выбор запускает нужный раунд.

При переборе прогресс показывает «Кеш ≈ … МБ/ГБ» (1024 МБ = 1 ГБ).
Это текущая оценка хранения ключей, результатов, массивов и BigInt двух поколений
кеша с однократным учётом общих терминальных результатов. Вытесненные записи
вычитаются. Поле API — `stats.cacheBytesEstimate`. Оценка зависит от устройства
V8 и не равна памяти процесса: GC, свободная ёмкость heap и временные объекты
в неё не включены. Для обновления индикатора кеш не обходится заново.

На графике вероятностей пунктиром показаны лучшие доступные шансы A и B из
позиции **перед каждым реальным действием**. Для каждой команды выбирается свой
максимум; это могут быть разные ходы, поэтому сумма пунктирных значений может
быть больше 100%. Шаг 0 сохраняет базовые шансы. Линии не являются отдельной
идеальной последовательностью: после каждого шага снова используется реальная позиция.

Линии из точек показывают худшие доступные шансы каждой команды из тех же
реальных позиций: минимумы выбираются независимо по точным долям BigInt.
Под графиком показаны лучшие и худшие шансы выбранного шага, округлённые до сотых.
При единственном допустимом ходе все варианты совпадают; шаг 0 сохраняет базу.

На графике «Влияние хода» три столбца идут слева направо: лучший допустимый
ход со штриховкой, сделанный ход со сплошной заливкой и «Худший вероятный ход»
с точечной заливкой. Влияние альтернатив — максимальный или минимальный шанс
команды автора после допустимого хода минус её шанс до хода из той же реальной
позиции. Подписи «Лучший», «Факт» и «Худший» показывают три значения до сотых.
При выборе шага указаны лучшие и худшие камни и края. Лучшее влияние всегда
неотрицательно, худшее — неположительно. При единственном допустимом действии,
включая обязательную выкладку или пас, все три значения нулевые.
Нажатие на любой столбец выбирает реальный шаг истории,
а не проигрывает альтернативный ход. Итоги игроков учитывают только реальные действия.
Лучший ход выбирается сравнением точных дробей BigInt, до округления процентов.

Для незавершённой позиции `P(s) = Σ W_a / Σ N_a`: выигрышные и общие листья
суммируются по всем уникальным допустимым продолжениям одного узла. Это среднее
долей вариантов с весами по числу листьев, а не среднее при равновероятном выборе
ходов. Например, варианты 10/100 и 60/300 дают исходную долю 70/400 = 17,5%,
а не 15%. Поэтому исходная оценка находится между худшей и лучшей, а при
одинаковых точных долях всех вариантов каждое влияние нулевое. Разные пути
к общей позиции сохраняют кратность. Завершённая позиция имеет один терминальный
лист и не имеет допустимых ходов; формула суммы детей к ней не применяется.
Эти свойства относятся к анализу с раскрытыми руками, а не к прогнозу действий людей.

Импакт игрока за раунд — сумма изменений шанса **его команды** после его собственных
ходов. Заход и пропуск также учитываются. Это описание изменения шансов, а не
оценка оптимальности или мастерства игрока. Итоги раунда не зависят от выбранного
шага истории. После выбранного раунда приложение последовательно досчитывает
остальные для таблицы «Импакт игроков по раундам и партии». Общая сумма появляется
только после расчёта всех раундов; до этого показаны прочерки и готовность N/M.
Расчёт можно отменить и продолжить кнопкой «Досчитать всю партию», сохранив
результаты уже готовых раундов. Во время расчёта доступна история выбранного раунда.
Повторное открытие раунда не удваивает вклад. Сумма нескольких изменений может
выходить за диапазон −100…100 и не обрезается.

В колонке «Изменение A», графике, альтернативах и итогах импакта используется обозначение `%`
для разницы вероятностей: 50% → 60% отображается как +10 %, без деления на прежние
50%. Числовая формула изменения в истории осталась прежней.

Вероятности, изменения, импакт и подписи графиков отображаются с двумя знаками
после запятой. Внутренние значения сохраняют большую точность, суммы считаются до
округления отображения. Ненулевая вероятность, округляющаяся в ноль, обозначена
«<0,01 %», а не нулём; аналогично «>99,99 %» для практически достоверного исхода.

В блоке «Возможные ходы» для каждого кандидата показана **потеря к лучшему**:
`L_a = P_лучший − P_a` для команды ходящего. Рядом с влиянием фактического
выбора показана «Упущенная возможность по анализатору». Положительное влияние
не исключает потери: улучшивший оценку ход может уступать другому варианту.
Под графиком разбор относится к ходу выбранного шага, а список альтернатив —
к следующему решению из выбранной позиции. На шаге 0 предыдущего решения нет;
в конце раунда последний ход доступен для разбора, но дальнейших действий нет.

Потери вычисляются из точных `wins/leaves`, а не из округлённых процентов,
и отображаются до сотых % Ненулевая потеря меньше 0,01 % обозначается
«<0,01 %», точный ноль — «0,00 %». Каждый точный максимум отмечен как
лучший; отметка «В игре» независима от этой оценки. Фактический ход дополнительно выделен закруглённой рамкой.
Пояснение находится под списком ходов; раскрывающиеся счётчики не выводятся.

«Вынужденный ход» означает единственное уникальное действие, включая пас.
«Равноценный выбор» — несколько действий с одинаковой точной долей для своей
команды; все они лучшие. «Разные оценки» — остальные позиции, в том числе
несколько равных лидеров и более слабые варианты. Совпадения округлённых
процентов недостаточно для равенства. Интерфейс показывает число лучших из всех вариантов.

Анализ использует раскрытые руки. Упущенная возможность по анализатору
не означает безусловную ошибку человека, который не видел чужих камней.
Доля листьев не является minimax-оценкой или прогнозом человеческой игры.
Суммы локальных потерь не равны потерянной вероятности победы в партии
и могут превышать 100 %

## Победа при рыбе

Начисления очков и поле `winner_team` проверяются по исходной спецификации.
**Аналитический победитель** определяется отдельно по согласованному правилу:

1. При выходе — команда вышедшего игрока.
2. При любой рыбе, завершающей партию, — победитель партии. При окончательной ничьей
   показывается третий исход «Ничья партии».
3. При рыбе, после которой партия продолжается, — команда рыбака, включая рыбу
   с яйцами. Рыбак — последний выложивший недубль; последующие дубли его не меняют.

Для альтернативных ветвей используется их собственный итоговый счёт, а не факт
последнего раунда в исходном файле. Рыба с яйцами — способ завершения, одновременно
с аналитической победой рыбака. Право фактического следующего захода проверяется
по спецификации: пока запись 0:0, начинает владелец 1–1 новой раздачи.

## Проверка входа и ограничения

[Схема](contracts/kozel-game.schema.json) и
[учебный журнал](contracts/kozel-game.example.json) взяты из `domino_spec/docs/formats`.
Поддерживается `kozel-game-v1`, варианты `withEggs` / `withoutEggs`, лимиты 50 / 101.
Правила игры взяты из `domino_spec/openspec/changes/add-kozel-fish-variants/specs/kozel-rules/spec.md`.

Проверяются повторные JSON-ключи (включая экранированные), структура, уникальность
игроков и мест, противоположность партнёров, все 28 камней, условия пересдачи,
право захода, очередь, ориентация, обязательность пропусков, своевременное окончание,
результаты раундов, запись/забор/яйца и завершение партии именно последним раундом.
Вход должен быть завершённой партией; неполные журналы не принимаются.
Предельный размер загрузки — 5 МБ, вложенность — 64, числовые поля — точные
безопасные целые JavaScript. Автоматических исправлений нет.

В наборе готовых образцов обнаружен ошибочный журнал
`2026-10-02-15-01-source-013-game-001.json`: неверный заход во втором раунде.
Он отклоняется с номером раунда и хода, даже несмотря на отсутствие `needs-review`.

Расчёт выполняется в одном отдельном worker. Прогресс показывает число рассчитанных
позиций, обращения к кешу и время; достоверный процент готовности заранее неизвестен.
Можно отменить и запустить раунд снова. Готовые анализы кешируются по содержимому
журнала и номеру раунда; в памяти хранятся последние восемь результатов. Кеш узлов
освобождается вместе с worker, готовая история остаётся для повторного просмотра.
Кеш узлов ограничен двумя миллионами записей в двух поколениях; старые записи
вытесняются. При повторной встрече вытесненной позиции она вычисляется заново.
Это ограничивает память, сохраняя полный перебор и точность всех результатов.
Трудоёмкость зависит от раздачи и может быть большой. При нехватке памяти приложение
покажет ошибку расчёта, не выдавая приблизительный результат за точный.

## Разработка и проверки

```powershell
npm.cmd test
npm.cmd run check
npm.cmd run analyze -- 'C:\Games\game.json' 1
npm.cmd run analyze -- 'C:\Games\game.json' validate
node tools/verify-examples.js 'C:\Projects\Home\domino_video_parser\out' --full
```

CLI выдаёт JSON со всей историей; прогресс пишет в stderr. Проверка образцов
сохраняет результаты и SHA-256 исходников в `.analysis/examples-report.json`.

Используется [AST Index](https://github.com/defendend/Claude-ast-index-search) 3.55.0,
локально закреплённый отдельным lock-файлом из проекта-парсера. `npm ci`
устанавливает его через postinstall и строит индекс; pretest/precheck
обновляют индекс. Обычный запуск сервера (`npm start` и корневые скрипты)
индекс не обновляет. Отдельная команда — `npm run index`.
Проектный хук [.codex/hooks.json](.codex/hooks.json) обновляет индекс при начале,
возобновлении и очистке сессии Codex (`startup`, `resume`, `clear`), но не при
сжатии контекста. Перед первым выполнением доверьте новый хук в Codex
(в CLI — `/hooks`). Команда работает также из подкаталогов проекта.
В версии 3.55.0 в этом каталоге без Git инкрементальное `update`
захватывает зависимости, поэтому хуки используют быстрый `rebuild`.

```powershell
npm.cmd run index
.\ast-index.cmd stats
.\ast-index.cmd outline src/game.js
.\ast-index.cmd refs settle --limit 20
.\ast-index.cmd explore 'round analysis probability'
```

Корни индекса: src/, public/, test/, tools/. Зависимости, контракты и данные
исключены. Глобальные настройки Codex и других проектов не меняются.
Правила — [AGENTS.md](AGENTS.md) и [.agents/rules/](.agents/rules/TOOL_USAGE_RULES.md).
OpenSpec перенесён из парсера с необходимыми скиллами и скриптами:
спецификация → падающий тест → реализация → проверки → архивирование.
Коммиты и публикация выполняются только по отдельному запросу.

Фактически выполненные проверки и результаты полного перебора образцов:
[отчёт](docs/validation.md).

## Источники по аналитике домино

[Каталог внешних источников](docs/domino-analysis-sources.md) содержит материалы
по командному домино 2×2, а также Mesa Quince, PlayDomino и статистику двух- и
трёхместных вариантов для сравнения. Указаны алгоритмы, результаты проверок
и отличия правил. Предложения по развитию и их приоритеты находятся в
[бэклоге](backlog.md).

Выбор раунда выполняется кнопками в боковой области «РАУНД» или в таблице
результатов. Выпадающего списка и отдельной кнопки расчёта нет: первый раунд
открывается автоматически, неготовый рассчитывается при выборе.

В «Возможных ходах» показаны разброс лучшей и худшей оценки и отрыв первого
кандидата от второго. При равных лидерах отрыв нулевой; при одном действии
второго кандидата нет. Метрики не означают уверенность или сложность для человека.

Сводка «Качество решений игроков» показывает для выбранного раунда и партии
число лучших из значимых решений, долю лучших, среднюю и максимальную потерю.
Вынужденные и полностью равноценные действия учтены отдельно. Средняя включает
нулевые потери лучших решений. Партия получает итог только после всех раундов;
повтор заменяет результат. При отсутствии значимых решений оценки обозначены
прочерками, а не идеальным качеством. У единственного хода в карточке нет
метки лучшего, потери, нулевого влияния и дублирующей сводки.

Обзор «Ключевые эпизоды раунда» отдельно показывает до пяти крупнейших
упущенных возможностей, ростов и снижений оценки и разбросов альтернатив.
Отбор использует точные доли до округления; равные значения идут по порядку
ходов. Один ход может попасть в несколько категорий. Кнопка открывает позицию
перед действием: в «Возможных ходах» видны фактический выбор и все лучшие
варианты, графики и история синхронизированы. Пустой список не означает
идеальную игру человека: оценка относится к модели с раскрытыми руками.
Проверки: [качество](docs/player-quality-verification.md),
[ключевые эпизоды](docs/key-episodes-verification.md).

Общий фильтр «Минимальное значение, %» ограничивает все категории по модулю
значения: по умолчанию не менее 3 %, включая ровно 3 %. Значение 0 показывает
все ненулевые эпизоды. Сравнение выполняется до округления, отдельно для
показателя каждой категории; история и оценки ходов сохраняются полностью.
Порог сохраняется при смене раунда до перезагрузки страницы.

В каждом кандидате раскрываются «Факты после хода»: остатки, дубли, покрытие,
ближайший пас и ответы партнёра после всех легальных ответов соперника.
Это проверенные переходы с раскрытыми руками, без причинных бонусов к W/N.

«Масти и контроль концов» в позиции и фактах кандидата показывает камни и
половинки по игрокам и командам. Дубль считается 1/2; закрытый конец не имеет
владельца. Новая масть означает только отсутствие значения в цепочке до хода.
