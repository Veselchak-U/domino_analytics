# Источник спецификации игры

Актуальный источник правил и JSON-формата: [Veselchak-U/domino_spec](https://github.com/Veselchak-U/domino_spec), основная ветка `main`. Адрес указан пользователем как источник обновлений для этого проекта.

Используемые материалы:

- [Описание формата](https://github.com/Veselchak-U/domino_spec/blob/main/docs/formats/README.md).
- [JSON Schema](https://github.com/Veselchak-U/domino_spec/blob/main/docs/formats/kozel-game.schema.json).
- [Пример формата](https://github.com/Veselchak-U/domino_spec/blob/main/docs/formats/kozel-game.example.json).
- [План правил игры](https://github.com/Veselchak-U/domino_spec/blob/main/openspec/changes/add-kozel-fish-variants/specs/kozel-rules/spec.md), на который ссылается README источника. На проверенной ревизии основные openspec/specs ещё не опубликованы; архивы не заменяют текущие документы.

## Порядок обновления

Перед изменением игрового контракта или правил проверить актуальную ветку источника, прочитать относящиеся к задаче материалы и зафиксировать commit, по которому выполнена сверка. Сравнить их с contracts/, игровым ядром и активными OpenSpec-изменениями. Если внешние пути изменились, начать с README репозитория.

Обновления локального контракта и поведения проводить в рамках разрешённой пользователем работы через OpenSpec и проверки. При запросе только спецификаций обновлять план, а не код приложения или исходные JSON. Примеры источника используются как справка; пользовательские журналы и соседние проекты не переписываются. При недоступности источника сообщать об этом и не объявлять локальную копию актуальной. Автоматические фоновые обновления не настроены.

Внешний репозиторий задаёт правила игры и входной формат; алгоритм W/N, аналитический победитель и архитектура этого приложения определяются его собственными спецификациями. Обнаруженные расхождения требуют явного разбора, а не молчаливой замены модели расчёта.

## Последняя сверка

Дата: 1 ноября 2026 года. Проверена ревизия [fef6b1bb864ada44727ea7f3b3fd273418dc4180](https://github.com/Veselchak-U/domino_spec/commit/fef6b1bb864ada44727ea7f3b3fd273418dc4180).

SHA-256 исходного файла docs/formats/kozel-game.schema.json этой ревизии: `faab7764cee886dc6a06ebe8da01cca67271be334ece74b374bb8176f1c9ef34`.

В источнике добавлено обязательное `playedAt`: дата и время начала партии по RFC 3339 с часовым поясом. Проверка `format: date-time` должна быть включена. Дата без времени, время без пояса, пустая строка и null недопустимы. Значение по умолчанию отсутствует; дата старого журнала должна быть указана явно. Поле записывается первым, перед format, но позиция ключа не является условием приёма JSON.

Добавлен необязательный `status`: отсутствие равно `complete`; для `complete` обязателен корневой `result`, для `incomplete` он запрещён. В обоих случаях нужен минимум один полностью завершённый раунд с полными `deal`, `moves`, `result`. Незавершённость всей партии дополнительно проверяется воспроизведением. Сохранять частичный раунд нельзя. Сервер анализа отклоняет `incomplete` по содержимому независимо от имени файла; загрузка для продолжения доступна в форме записи.

В первом раунде обязателен заход 1–1. С яйцами до открытия записанного счёта следующий раунд снова начинается с 1–1. Без яиц со второго раунда заходит завершивший предыдущий раунд любым камнем, даже при счёте 0:0; после открытия счёта это же правило действует с яйцами. Версия правил результатов повышена до `rules: 2`, API остаётся v1, схема БД не меняется.

Локальная contracts/kozel-game.schema.json синхронизирована с этой ревизией. Проверка date-time включена в переносимый standalone-валидатор. Исторический kozel-game.example.json, contracts/demo-game.json и пользовательские журналы не переписаны.
