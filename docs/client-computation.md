# Клиентский расчёт и серверное хранение

Браузер выполняет полную проверку журнала, правила, начисления, точный перебор,
анализ раундов и веток и учебные упражнения. Backend хранит исходники и готовые
компактные результаты в SQLite; он не импортирует игровой движок или solver.
Каждая вкладка имеет собственный Web Worker, отмена не затрагивает других клиентов.
GPU не требуется и в текущем движке не используется.

## Компоненты и состояние

| Компонент | Ответственность |
|---|---|
| shared/input, game, solver, analysis, facts, lessons | Одно переносимое игровое ядро для браузера и CLI |
| public/compute-worker | Полное воспроизведение и точный расчёт вне UI |
| public/computation | Один активный запуск, прогресс, жёсткая отмена, отбрасывание поздних сообщений |
| public/analysis-client | Кеш компактных результатов, проверка envelope, исходники и очередь неопубликованных результатов в памяти |
| src/frontend | Статика по явному списку и прокси на один backend, без БД |
| src/server, storage | Ограниченная структурная проверка, REST API v1, атомарная запись SQLite |

У каждого запуска новый ограниченный кеш поддеревьев. Кеш вытесняет только
сохранённые промежуточные результаты, не ветви дерева: потерянные записи считаются
заново точно. По умолчанию 250 000 позиций; в UI доступны 50 000 и 2 000 000.
Это предел записей, не обещание точного объёма heap.

После завершения worker остаётся загруженным для следующего запроса; ссылки на
кеш завершённого solver не сохраняются. Это позволяет использовать уже загруженный
вычислитель при недоступном API без повторной загрузки модулей. Отмена/ошибка
завершает worker; повтор создаёт новый. Ни дерево, ни граф, ни живой кеш на сервер
не передаются. Незавершённая работа не публикуется.

## Идентичность и источник JSON

Актуальная спецификация: [domino_spec](game-spec-source.md). Поле playedAt обязательно:
начало партии по RFC 3339 с часовым поясом, без значения по умолчанию.
Позиция первого ключа — соглашение записи, а не условие приёма.

gameId — SHA-256 канонического объекта с моментом playedAt в UTC без потери дробных
секунд и отсортированными четырьмя именами игроков. Имена сравниваются с учётом
регистра/пробелов. Порядок команд/игроков и имя файла не меняют идентичность.

Отдельный digest содержимого нормализует порядок ключей, команд, игроков и камней
начальных рук, но сохраняет порядок ходов и раундов. Эквивалентный повтор возвращает
первый исходный текст, имя и дату загрузки. Другое содержание той же партии даёт
409 GAME_SOURCE_CONFLICT без перезаписи и без применения старого кеша к новому журналу.
На диске пользовательские JSON не изменяются; первый исходный текст хранится в БД
без переформатирования.

## API v1

Основной префикс /api/v1; /api — равнозначный алиас. Новая версия API не вводится.
Frontend и backend обновляются совместно, совместимость старого UI не обещается.

| Метод и путь | Результат |
|---|---|
| GET /health | Статус БД и computation:client |
| POST /import | {text,name}; 201 новая партия, 200 эквивалентный повтор, 409 конфликт |
| GET /games?limit=20&cursor=… | Карточки с именем/датой и готовыми раундами; максимум 100 на страницу |
| GET /games/:id | Карточка партии, validation:structural-only |
| GET /games/:id/source | Неизменённый исходный текст JSON |
| GET /games/:id/analyses?limit=20&cursor=… | Только manifest: номер, ключ, версия и hash без payload |
| GET /results/:key | Совместимый завершённый envelope и cached:true либо 404 |
| PUT /results/:key | 201 первая запись, 200 эквивалентный повтор, 409 RESULT_CONFLICT |
| GET /examples | Список разрешённых локальных файлов |
| GET /examples/:id/source | Только исходник; demo — актуальный синтетический пример |
| GET /lessons | Статический каталог без расчёта; определения поставляются вместе с UI |

Прежние /analyze, /branch, /lesson, /jobs и POST /example дают
410 CLIENT_COMPUTATION_REQUIRED. Серверной очереди и серверных вычислительных jobs нет.

Envelope содержит formatVersion:1, descriptor, result, payloadHash. Descriptor включает
версии rules/engine/metrics/schema и параметры раунда, ветки или урока. Для урока
включён digest определений. Ключ — SHA-256 descriptor с рекурсивно упорядоченными
ключами объектов и сохранённым порядком массивов. PayloadHash исключает только
корневой stats: время и попадания в кеш могут различаться между компьютерами.

Сервер назначает provenance: producer:browser, verification:structural-only.
Эта отметка и хеш не доказывают правильность перебора. Библиотека общая для доверенных
клиентов в существующей закрытой модели доступа, без учётных записей и приватных разделов.

## Проверки и ограничения

Backend проверяет схему исходника, playedAt, уникальные имена/места для ключа, формат
запроса, версии/digest, существование партии и границы раунда/шага. У результатов
проверяет структуру, точные счётчики и суммы исходов, fish/eggs и границы глубины.
Он не воспроизводит игровые переходы, не сверяет начисления и не выполняет solver.
Браузер полностью проверяет даже журнал из сохранённой библиотеки.

Лимиты: исходник 5 МиБ, тело импорта 11 МиБ, тело результата 16 МиБ; глубина JSON 64,
1024 раунда, 128 действий, 129 шагов, 56 альтернатив на шаг, счётчик до 1024 цифр.
JSON с повторными ключами отклоняется. Два одновременных слота загрузки не занимают
клиентские расчёты; чтения не используют эти слоты. Ошибки: 400 структура/хеш,
404 отсутствие, 413 размер, 415 Content-Type/сжатие, 422 версия, 429 занятые слоты,
503 хранилище. Отсутствует усечение или приближённый ответ вместо ошибки.

## Сохранение, отключение сети и несколько клиентов

Результат отображается сразу после вычисления. Статусы различают локальную готовность,
сохранение, подтверждённую запись, ошибку и конфликт. При отказе API исходник и результат
остаются в памяти вкладки. «Повторить сохранение» повторяет импорт/PUT без solver.
После потери ответа идемпотентный PUT возвращает уже зафиксированный результат.
Конфликт не перезаписывается автоматически.

Два клиента могут независимо посчитать один запрос; первая запись фиксируется,
эквивалентный повтор не создаёт дубль, иное математическое содержание даёт 409.
Закрытие вкладки теряет живое дерево и неопубликованные данные; межсессионного
локального outbox и восстановления частичного перебора нет.

Несколько доверенных клиентов используют отдельные SSH-туннели на localhost:3210.
Другие локальные порты разрешаются точным списком DOMINO_ALLOWED_HOSTS frontend
и DOMINO_ALLOWED_ORIGINS backend; wildcard не добавляется. В npm start разрешённые
Host автоматически входят в разрешённые HTTP Origin. Игровые данные не передаются
внешним сервисам или телеметрии.

## Схема БД и поставка

Текущая схема SQLite — 3, таблицы games/results. По прямому указанию пользователя
старая схема заменяется новой пустой без миграции, переноса записей или legacy.
Замена выполняется транзакционно, затем старые страницы освобождаются.
Более новая неизвестная схема не изменяется. Повторное открытие версии 3 сохраняет
новые партии и готовые результаты. Прежние исходные файлы на диске не затрагиваются.

Резервная копия актуальной БД делается прежним backup-инструментом с проверкой
целостности. При откате старому релизу нужна отдельная БД его схемы, автоматического
переноса данных нет. Docker Desktop сохраняет постоянный том и два сервиса;
backend-образ не содержит игрового ядра и runtime-зависимостей npm.

Standalone-валидатор и manifest уроков обновляются командой npm run generate:contracts.
npm run check проверяет их соответствие схеме/определениям, синтаксис и ссылки правил.
Обычный запуск приложения не требует сборки. Node CLI использует то же чистое ядро;
Node worker в tools/verify-examples — отдельный локальный инструмент, не часть HTTP backend.

## Воспроизводимая проверка

Node-тесты: npm test. Браузер: node tools/browser-verification-server.js,
затем открыть http://127.0.0.1:3220/verify. Проверка использует отдельную тестовую БД
в памяти и явно датированную синтетическую копию test/fixtures/real-game.json;
рабочая БД не открывается. Тестовый сервер остановить Ctrl+C.

Эталон: 7 328 406 листьев, победы [4 255 456,3 072 949,1], глубина 40, 16 шагов.
Проверяются отзывчивость, отключение API, повтор сохранения без solver, общий кеш,
независимость/отмена вычислителей, урок, неверный журнал и повреждённый envelope.
Затем два полных клиентских расчёта идут параллельно с чтением третьим клиентом и
публикуют готовые результаты. Профили сервера сохраняются в .analysis/browser-verification/.

Тесты БД проверяют замену старой схемы, повторное открытие актуальной, версии,
конкурентные записи, конфликт, точные строки BigInt, отказ записи и согласованный backup.
Docker-smoke считает на клиентском компьютере и только загружает/читает данные.
Фактическая сборка/пересоздание Docker-контейнеров требует установленного Docker;
при его отсутствии статические проверки и shell-тесты не заменяют запуск контейнеров.
