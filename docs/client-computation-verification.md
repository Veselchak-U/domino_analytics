# Проверка переноса вычислений в браузер

Дата: 1 ноября 2026 года. Изменение move-analysis-to-browser.

## Автоматические проверки

npm test: 129 проверок, 129 успешных, без пропусков. npm run check: синтаксис,
ссылки правил и соответствие сгенерированных валидатора/manifest исходникам — успешно.
PowerShell-парсер проверил start.ps1 без ошибок. git diff --check — без ошибок.

Покрыты точность исходов, BigInt, кратность/дедупликация, оба варианта рыбы,
начисления и ничья, ориентация, сохранение 28 камней, ветки и уроки; ошибки playedAt,
нормализация времени без потери точности, дубли и конфликты источников/результатов,
перезапуск/backup, замена старой схемы без legacy, отказ более новой схемы.

HTTP-проверки включают два занятых слота с доступными чтениями, 429, границу
исходника 5 МиБ и первое превышение, границу тела результата 16 МиБ и первое
превышение, 415 для сжатия/Content-Type и 503 при искусственном отказе записи SQLite.
Структурно допустимый журнал с неверным игроком принят API и отвергнут клиентским
воспроизведением: сервер действительно не исполняет игровые правила.

Проверен граф импортов backend-образа: только Node builtins и переносимые
структурные проверки; game/solver/analysis/lessons в нём отсутствуют. Docker-контекст
включает новый demo-game.json и исключает пользовательские журналы и БД.

## Реальный браузер

Прогон tools/browser-verification-server.js + /verify в браузере Codex завершён
со статусом BROWSER VERIFICATION PASSED. Использован отдельный сервер с БД в памяти,
рабочая БД не открывалась. Исторический fixture прочитан в копию с явным синтетическим
playedAt; исходный файл не менялся.

Контрольный результат: 7 328 406 листьев, wins [4 255 456,3 072 949,1], depth 40,
16 шагов. Интерфейс оставался отзывчивым. Проверены локальный результат при отказе
API, повтор сохранения без solver, повтор в памяти, общий кеш для другого клиента,
жёсткая отмена и независимость вычислителей, повтор после отмены, урок без импорта,
неверный журнал, отказ загрузки Worker и повреждённый envelope.

Дополнительно в основном UI проверены открытие сохранённой партии, восстановление
графиков/качества, переход к концу и назад, ветка из позиции 14, возврат в реальную
историю, ответ в тренировке и загрузка рисунка 9 командной тактики с сокрытыми оценками.

## Нагрузка сервера

Оборудование: Intel Core i7-13700K, 24 доступных логических процессора; Node v22.15.1,
Windows. Два независимых браузерных worker параллельно считали полный контрольный
раунд. Каждые 100 мс шли последовательные чтения health, каталога и готового анализа;
после вычисления выполнены две одновременные публикации без дублей. Затем выполнен
контрольный прогон тех же чтений без вычислителей.

| Показатель | Два клиентских расчёта и публикации | Контроль без расчётов |
|---|---:|---:|
| Время прогона | 23,49 с | 3,01 с |
| CPU серверного процесса | 1,219 с | 0,250 с |
| RSS до/после | 55,4 / 64,1 МиБ | 64,1 / 72,4 МиБ |
| Групп из трёх чтений | 234 | 29 |
| Максимальное время группы чтений | 16,0 мс | 17,5 мс |

Измерения относятся к одному тестовому Node-процессу с обоими HTTP-серверами,
включают чтения/JSON и публикации; это не универсальная гарантия времени ответа.
Перебор выполнялся в браузерных workers. Различия GC и короткий контрольный период
не позволяют интерпретировать проценты CPU как строгий benchmark производительности.
Точные JSON-профили сохранены в .analysis/browser-verification/load-report-1.json
и load-report-2.json.

## Ограничение проверки поставки

Docker в окружении недоступен. Фактическая сборка образов и пересоздание контейнеров
не выполнялись. Проверены состав Dockerfile/.dockerignore/Compose, сохранение тома,
Node HTTP/SQLite и shell-тест установки, повреждённого релиза, обновления и отката.
Для реальной контейнерной приёмки использовать tools/docker-smoke.js seed/verify
на машине с Docker; расчёт seed выполняется на клиентском компьютере.
